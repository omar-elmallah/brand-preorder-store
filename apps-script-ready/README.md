# التشغيل اليدوي — أربعة ملفات فقط

الملفات مجهزة للنسخ مباشرة؛ لا تحتاج npm أو build أو clasp داخل Apps Script. لم يُجهز شيت في حساب Google بعد؛ أنت ستشغّل دالة الإعداد.

## 1. ابدأ من الشيت الجديد

أنشئ **Google Sheet جديدًا وفارغًا** خاصًا بالمتجر، ثم افتح منه **Extensions → Apps Script** وسمِّ المشروع. لا تفتح شيت أو مشروع NAGY STUDIO. الإعداد سيجهز هذا الشيت نفسه؛ لن ينشئ شيتًا ثانيًا.

## 2. انسخ محتويات الملفات الأربعة

استخدم مجلد `apps-script-ready` وحده، وانسخ محتوى كل ملف كاملًا:

| الملف في المحرر | طريقة إضافته | المحتوى |
|---|---|---|
| `Code.gs` | Script؛ استبدل محتوى الملف الافتراضي | [Code.gs](../apps-script-ready/Code.gs): الخادم كاملًا |
| `Index.html` | **+ → HTML**، الاسم `Index` | [Index.html](../apps-script-ready/Index.html): المتجر والتنسيق والسكربت |
| `Admin.html` | **+ → HTML**، الاسم `Admin` | [Admin.html](../apps-script-ready/Admin.html): لوحة الإدارة |
| `appsscript.json` | أظهر البيان الموجود ثم استبدل محتواه | [appsscript.json](../apps-script-ready/appsscript.json) |

لإظهار البيان: **Project Settings → Show “appsscript.json” manifest file in editor**. احفظ الملفات؛ المنطقة الزمنية `Africa/Cairo`.

لا تنسخ `src` مع الحزمة؛ وحداته مدمجة بالفعل في `Code.gs` و`Index.html`. لا تضف `README.md` أو `SCHEMA.md` للمحرر، ولا تلصق JSON داخل `Code.gs`.

## 3. ضع بريدَي الإدارة

من **Project Settings → Script Properties → Add script property**:

- **Property:** `STORE_ADMIN_EMAILS`
- **Value:** بريدك وبريد مصطفى الفعليان، بينهما فاصلة إنجليزية؛ مثال للتنسيق فقط: `omar@example.com,mustafa@example.com`.

يدعم حسابًا أو حسابين؛ حساب تشغيل الإعداد يجب أن يكون ضمنهما. لا تنشئ `STORE_SPREADSHEET_ID` يدويًا ولا تضع كلمات مرور في HTML.

## 4. شغّل الإعداد

اختر **`setupStore` → Run** من المحرر. راجع وامنح صلاحيات **Google Sheets** و**معرفة بريد حساب Google**. نطاق Sheets واسع تقنيًا، والكود يقصر التشغيل على الشيت المرتبط ومعرفه وعلامة مشروعه.

عند النجاح يظهر رابط **نفس الشيت** وملخص التبويبات في **Execution log**، ويُحفظ المعرف تلقائيًا. إعادة التشغيل تحفظ البيانات والقيم المعدلة ولا تكرر البذور. الشيت غير الفارغ وغير المعلّم للمشروع، أو تعارض المعرف، أو الأعمدة القديمة غير المطابقة، يسبب خطأ واضحًا قبل التعديل. لا تمسح مشروعًا سابقًا لتجاوز الخطأ.

## 5. تأكد من النتيجة

يُنشئ الإعداد العناوين والتنسيق والتثبيت وقواعد التحقق تلقائيًا. بعد أول نجاح تكون صفوف البيانات:

| التبويب | الصفوف |
|---|---:|
| `Products` | 1 |
| `Variants` | 8: أسود وبرجندي × 4 مقاسات تجريبية |
| `SizeGuide` | 4 تجريبية |
| `Orders` | 0 |
| `OrderItems` | 0 |
| `Shipping` | 2 تجريبيتان |
| `Settings` | 17 |
| `AuditLog` | 1 سجل إعداد |

قد تظل ورقة Google الافتراضية الفارغة موجودة؛ لا يحذفها الإعداد. [SCHEMA.md](../apps-script-ready/SCHEMA.md) يسرد الأعمدة بالترتيب والإعدادات الفعلية؛ لا تحتاج لكتابتها يدويًا.

اترك `test_mode=TRUE` و`orders_open=FALSE` و`payment_method=demo` و`real_content_confirmed=FALSE`. الأسعار والمقاسات للتجربة؛ `65000` قرش = 650 جنيهًا.

## 6. انشر المتجر للتجربة

**Deploy → New deployment → Web app**:

- **Execute as:** `Me`.
- **Who has access:** `Only myself` أولًا.

احفظ رابط `/exec` وافتحه للمتجر، بدون `?admin=1`. لا تجعل الشيت عامًا.

## 7. انشر الإدارة

أنشئ نشر **Web app** ثانيًا في نفس المشروع:

- **Execute as:** `User accessing the web app`.
- **Who has access:** حسابات Google المسجلة أو نطاق Workspace حسب المتاح.

افتح رابط هذا النشر مع **`?admin=1`**؛ إن وجدت معاملات سابقة استخدم `&admin=1`. شارك الشيت الجديد مع مصطفى **Editor**، واختبر الحسابين بعد موافقات Google. محرر الشيت المرتبط قد يصل أيضًا إلى السكربت؛ اعتبره شخصًا موثوقًا بالكامل.

الخادم يشترط بريدًا ضمن القائمة وتطابق المستخدم الفعلي مع مستخدم التنفيذ. البريد الفارغ أو الحساب الثالث مرفوض؛ الرابط وحده لا يمنح صلاحية. إذا منعت سياسة Google نوع النشر أو إظهار الهوية، لا يوجد تجاوز بكلمة مرور؛ يلزم حل إعداد الحساب والنشر.

## 8. أرسل أول طلب تجريبي

افتح المتجر بحساب المالك، واختر اللون والمقاس والمحافظة وأدخل بيانات اختبار. بعد الإرسال احتفظ برقم الطلب، وافتح الإدارة واختر **تجريبي**؛ يجب ظهوره مرة واحدة مع بنوده وحالة دفع **غير مدفوع**.

نفّذ [اختبارات Google](../docs/GOOGLE_TESTS.md). قبل البيع الحقيقي اعتمد الصور والأسعار والمقاسات والشحن والمواعيد والدفع والسياسات، ثم افتح البيع يدويًا من الإدارة. تغيير وصول المتجر إلى `Anyone` قرار يدوي مستقل بعد المراجعة؛ لا يحدث تلقائيًا.

طلبات الموقع بعد النشر تستخدم المعرف المحفوظ عبر `openById`؛ لا تعتمد على وجود شيت نشط عند الزائر. اختبارات Google الفعلية والنشر لم تُنفّذ من هذا التسليم.
