# متجر ملابس عربي — Google Apps Script + Google Sheets

نسخة أولى مستقلة لبراند عمر ومصطفى: سويت شيرت بلونين، وبيع بنظام الطلب المسبق. الواجهة عربية RTL، والخادم Google Apps Script، والتخزين في Google Sheet جديد وخاص يجهزه المشروع داخل الملف الذي تبدأ منه. لا يحتاج العميل إلى حساب، ولا توجد بوابة دفع أو بيانات بطاقات.

المشروع يبدأ **بوضع تجريبي**، باسم `BRAND NAME`، وصور توضيحية وقياسات وأسعار وشحن تجريبيين. بيانات التجربة ليست مواصفات أو التزامات للمنتج الحقيقي. البيع الحقيقي مغلق افتراضيًا، ولم يُنشر هذا المشروع على Google تلقائيًا.

لم تُقرأ أو تُنسخ أي ملفات أو شيتات أو مفاتيح أو عمليات نشر من NAGY STUDIO. ابدأ بشيت جديد فارغ، وافتح منه مشروع Apps Script مرتبطًا جديدًا لهذا المتجر؛ لا تلصق الملفات داخل مشروع سابق ولا تضع معرف شيت سابق في الإعدادات.

## النسخة الجاهزة للنسخ اليدوي

ابدأ من مجلد [apps-script-ready](apps-script-ready): فيه **أربعة ملفات فقط للمحرر**: `Code.gs` و`Index.html` و`Admin.html` و`appsscript.json`. [دليل التشغيل اليدوي بالترتيب](docs/MANUAL_SETUP.md) يشرح إنشاء الشيت الفارغ والملفات والصلاحيات وفحص التبويبات والنشرين؛ لا تحتاج Git أو Node أو clasp. راجع [مخطط التبويبات والإعدادات](apps-script-ready/SCHEMA.md) عند تعديل البيانات. `README.md` و`SCHEMA.md` دليلان ولا يُضافان إلى محرر Apps Script.

## ملف Excel الجاهز

[تحميل ملف تجهيز المتجر Excel](https://github.com/omar-elmallah/brand-preorder-store/raw/refs/heads/main/templates/brand-store-template.xlsx). يحتوي الجداول الثمانية، ودليلًا عربيًا وقائمة تجهيز، مع بيانات تجريبية فقط. راجع [دليل Excel ونقل القيم](docs/EXCEL_GUIDE.md)؛ الربط التشغيلي يظل عبر الشيت الجديد الذي تبدأ منه وتجهزه `setupStore()`، وليس باستبدال معرفه بملف Excel محوّل.

## أسرع تشغيل على Google

1. أنشئ **Google Sheet جديدًا فارغًا**، ثم افتح **Extensions → Apps Script** من داخله.
2. انسخ الملفات الأربعة من [apps-script-ready](apps-script-ready) إلى المحرر بالأسماء والأنواع الموضحة في [دليل التشغيل اليدوي](docs/MANUAL_SETUP.md). لا تنسخ معها ملفات `src`؛ النسخة الجاهزة تدمجها بالفعل.
3. أضف خاصية السكربت `STORE_ADMIN_EMAILS` ببريدَي عمر ومصطفى الفعليين، مفصولين بفاصلة إنجليزية. شغّل `setupStore()` بحساب موجود في القائمة، وراجع وامنح صلاحيات Sheets والبريد.
4. افحص التبويبات الثمانية وبيانات الديمو والإعدادات: `test_mode=TRUE` و`orders_open=FALSE` و`payment_method=demo`. يجهز الإعداد **نفس الشيت** ويحفظ `STORE_SPREADSHEET_ID` تلقائيًا؛ لا تنشئ هذه الخاصية أو تغيّرها يدويًا.
5. أنشئ نشر Web app للمتجر: التنفيذ باسم **Me** والوصول **Only myself** في أول تجربة. وأنشئ نشرًا ثانيًا للإدارة: التنفيذ باسم **User accessing the web app** ووصول بحساب Google/النطاق المتاح. أضف `?admin=1` إلى رابط نشر الإدارة.
6. شارك الشيت الجديد فقط مع مصطفى كـ Editor، واختبر دخول الحسابين المصرح لهما، ثم أرسل طلبًا تجريبيًا وافحص ظهوره مرة واحدة في الإدارة. نفّذ [اختبارات Google](docs/GOOGLE_TESTS.md) قبل إتاحة المتجر للعامة يدويًا.

يلزم بريد مصرح وتطابق هوية المستخدم الفعلي مع هوية التنفيذ لكل عملية إدارية. الهوية الفارغة أو غير المطابقة مرفوضة؛ سياسات Google/Workspace قد تحد من النشر أو الموافقة، ولا توجد كلمة مرور بديلة داخل الواجهة. مشاركة الشيت تعني الثقة بمحرريه؛ قد تمنحهم Google أيضًا الوصول إلى السكربت المرتبط. لا تستخدم رابط نشر التنفيذ باسم المالك لإدارة مصطفى. الرابط وحده لا يمنح صلاحية، ولا تجعل الشيت عامًا.

`setupStore()` يرفض قبل التعديل أي شيت غير فارغ غير مخصص لهذا المشروع، أو تعارضًا بين الشيت المرتبط والمعرف المحفوظ، أو علامة مشروع آخر. إعادة التشغيل تكمل النواقص دون استبدال بياناتك أو تكرار بذور الديمو. بعد اكتمال أول تهيئة لا يعيد الإعداد إضافة صفوف الديمو التي حذفتها عمدًا، حتى في وضع التجربة. عند تشغيل المتجر المنشور يعتمد الخادم على المعرف المحفوظ، لا على شيت نشط عند الزائر.

## ما الذي يعمل

- عرض المنتج، واختيار اللون والمقاس والكمية، وجدول قياسات، وسياسات الشحن والاستبدال والاسترجاع والتواصل.
- إظهار الطلب المسبق وموعد تجهيز الطلب للشحن منفصلًا عن مدة التوصيل، وحساب القطع والشحن والإجمالي قبل التأكيد.
- التحقق من المنتج والمتغير والمحافظة والكميات والحقول والهاتف على الخادم، وحساب السعر من الشيت؛ قيم المتصفح ليست مرجعًا ماليًا.
- إرسال طلب تجريبي أو حقيقي وفق إعدادات الخادم، مع مفتاح منع التكرار وإمكانية إعادة المحاولة، ومعالجة عمليات الحفظ غير المكتملة.
- إدارة الطلبات والقطع، والبحث والتصفية، وحالات الطلب والدفع المستقلتين، وتسجيل التحصيل والاسترداد إداريًا، وروابط واتساب للفتح والإرسال اليدوي.
- ملخص قيمة الطلبات والقطع حسب اللون والمقاس، والتحصيل والاستردادات بصورة مستقلة، مع فصل بيانات التجربة عن الحقيقية.
- سجل للتغييرات الإدارية المهمة دون نسخ العنوان أو الهاتف أو اسم العميل إلى سجل التدقيق.

## تعديل البيانات وإعداد الإطلاق

تُعدّل إعدادات البراند والنصوص عبر الإدارة أو `Settings`. تُعدّل المنتجات والمتغيرات والمقاسات والمحافظات في الشيت الخاص. لا تعدّل `Orders` أو `OrderItems` أو `AuditLog` يدويًا؛ استخدم الإدارة حتى تعمل معالجة السعة والدفع والتدقيق بصورة متسقة. الوصول المباشر إلى الشيت متاح للمحررين الموثوقين، لذا يظل هذا التزامًا تشغيليًا، وليس قيدًا يمكن للتطبيق فرضه على محرر Google Sheet.

| الجدول | أهم الحقول ومعناها |
|---|---|
| `Products` | `id` ثابت، الاسم والوصف والخامة والقصة، `image_urls` مصفوفة JSON لروابط HTTPS، و`active` و`is_demo` |
| `Variants` | `id` هو SKU ثابت، و`product_id`، واللون والمقاس، و`price_minor`، والتفعيل، و`preorder_limit` اختياري لكل SKU |
| `SizeGuide` | `size` وقياسات السنتيمتر وملاحظاتها؛ قياسات الديمو ليست قياسات المنتج |
| `Shipping` | معرف محافظة ثابت، الاسم، `fee_minor`، ومدة التوصيل بعد الشحن، والتفعيل |
| `Settings` | `key` ثابت و`value` والوصف؛ لا تغيّر أسماء المفاتيح |
| `Orders` | العميل والإجماليات وحالة الطلب والدفع ومصدر الزيارة وسجل معاملة الحفظ |
| `OrderItems` | نسخة السعر واللون والمقاس والاسم والكمية وقت الطلب؛ لا تتغير بتغيير الكتالوج لاحقًا |
| `AuditLog` | منفّذ التعديل ونوعه وتوقيته والقيم التشغيلية الضرورية |

جميع الأموال أعداد صحيحة **بالقرش المصري**: `65000` تعني 650 جنيهًا، و`6000` تعني 60 جنيهًا. لا تكتب `650` إذا كنت تقصد 650 جنيهًا، ولا تستخدم نصًا مثل `650 EGP` أو كسور جنيه عائمة. `preorder_limit` الفارغ يعني عدم تحديد سقف SKU؛ القيمة `0` تعني عدم وجود سعة. المعرفات ثابتة وليست أرقام صفوف؛ لا تعِد استخدام معرف SKU لمنتج مختلف.

مثال `image_urls` بعد إضافة الصور الحقيقية المعتمدة:

```json
["https://your-image-host.example/black-front.jpg", "https://your-image-host.example/burgundy-front.jpg"]
```

استبدل المثال بروابط صور تملك حق استخدامها ويمكن لزوار المتجر فتحها دون تسجيل دخول. صور Google Drive الخاصة أو صفحة مشاركة Drive ليست بالضرورة رابط صورة صالحًا. اختبر العرض على هاتف؛ لا تفتح مشاركة **الشيت** للعامة لحل مشكلة الصور.

للتجهيز الحقيقي: أضف منتجًا ومتغيرات ومقاسات وشحنًا حقيقيًا بمعرفات جديدة و`is_demo=false`، وراجع التفعيل. عطّل صفوف الديمو في Products وVariants وShipping بدل تحويل الطلبات التجريبية إلى حقيقية. في SizeGuide احذف صفوف القياسات التجريبية عند إدخال القياسات الحقيقية، لأن هذا الجدول لا يملك حقل active. لا تحذف الطلبات التجريبية أو تحولها إلى حقيقية. اختَر طريقة الدفع وأكمل المواعيد والسياسات والأسعار. بعد المراجعة الفعلية فقط اضبط `real_content_confirmed=true`. راجع [قائمة الإطلاق](docs/LAUNCH_CHECKLIST.md)، ثم غيّر `test_mode=false` و`orders_open=true` يدويًا من الإدارة. تفعيل الزر وحده لا يتجاوز فحص جاهزية الخادم.

## الطلب والدفع والسعة

حالات الطلب: جديد، مؤكد، قيد التجهيز، تم الشحن، تم التسليم، ملغي، مرتجع. حالة الدفع مستقلة: غير مدفوع، مدفوع جزئيًا، مدفوع، مسترد. اختيار `cod` لا يسجل أي تحصيل تلقائيًا. اختيار `manual_transfer` لا يثبت وصول التحويل؛ سجّل التحصيل من الإدارة بعد تحقق فعلي، مع ملاحظة مرجعية لا تحتوي أسرارًا مصرفية. لا يجمع المشروع بيانات بطاقات أو يرسل رسائل واتساب تلقائيًا.

مفتاح `idempotency_key` يحافظ على نفس الطلب عند تكرار الضغط أو إعادة محاولة الإرسال. تعديل الحمولة مع نفس المفتاح يُرفض؛ بعد نجاح الطلب ابدأ طلبًا جديدًا من الواجهة. إذا انقطع الاتصال لا تفترض الفشل ولا تسجّل طلبًا جديدًا عمدًا: أعد المحاولة بنفس بيانات الطلب ومفتاحه، أو ابحث عنه إداريًا. لا تشارك مفاتيح الطلبات.

الحفظ يستخدم قفل المشروع وحالة معاملة داخلية. لا يُعرض النجاح قبل اكتمال الطلب وبنوده. Sheets ليس قاعدة بيانات بمعاملات ACID؛ عند انقطاع Google أو انتهاء المهلة قد توجد معاملة معلقة، وتتعامل الاستعادة معها قبل العمليات التالية. استخدم زر استعادة العمليات المعلقة في الإدارة، ثم راجع النتيجة والطلبات. تُحسب السعة من السجل، مع فصل التجربة والحقيقي، لتجنب خصمها أو إرجاعها أكثر من مرة. إلغاء طلب لا يعني استرداد المال تلقائيًا، وتسجيل الاسترداد لا يغير حالة الطلب تلقائيًا.

## الاختبارات والمعاينة المحلية

يلزم Node.js حديث. لا توجد اعتماديات مطلوبة لتشغيل المتجر على Google Apps Script.

```sh
npm test
npm run check
npm run test:browser:ready
npm run preview
```

المعاينة أداة تطوير محلية ببيانات اختبار، وليست نشرًا للبيع ولا دليلًا على نجاح صلاحيات Google. استخدم الرابط الذي يطبعه الأمر. بيانات المعاينة مؤقتة في الذاكرة وتُمسح عند إيقاف الخادم، ولا تُرسل إلى شيت حقيقي. لوحة المعاينة تمنح إدارة تجريبية تلقائيًا؛ لا تختبر مصادقة Google فيها. المعاينة مربوطة على 127.0.0.1 فقط وتمنع تفعيل البيع الحقيقي. اختبارات Node تتحقق من المنطق باستخدام بدائل لخدمات Apps Script؛ لا تثبت OAuth أو `Session` أو `LockService` أو HTML Service الفعلية. راجع نتيجة الاختبارات المرفقة و[قائمة اختبارات Google](docs/GOOGLE_TESTS.md)؛ اختبارات Google لم تُنفذ من هذا التسليم المحلي.

اختبار المتصفح الاختياري: `npm run test:browser`. يحتاج Playwright للتطوير فقط: `npm install --no-save playwright`، ومتصفح Chromium مثبتًا؛ أو `npx playwright install chromium`. يمكن تحديد المتصفح عبر `CHROMIUM_EXECUTABLE`. الاختبار يشغّل خادم معاينة معزولًا ويغلقه تلقائيًا، ويختبر فقدان استجابة طلب محفوظ ثم إعادة المحاولة دون تكرار، وUTM وخصوصية أحداث القياس. لا تنسخ أدوات Node إلى Apps Script.

راجع [نتائج التحقق المحلي](docs/VALIDATION.md). للمطورين فقط: عند تعديل وحدات `src` شغّل `npm run prepare:apps-script` لتحديث مجلد النسخ الجاهز؛ لا يحتاج مستخدم Apps Script إلى هذا الأمر أو إلى أي build بعد النسخ.

## clasp اختياري

النسخة في `apps-script-ready` تكفي للنسخ اليدوي. للتطوير من الوحدات الأصلية في `src`، إذا أردت `clasp`، ثبّته من المصدر الرسمي وفعّل Apps Script API لحسابك. اربط **المشروع الجديد المرتبط بالشيت الجديد**؛ لا تستخدم `.clasp.json` من NAGY STUDIO أو أي مشروع سابق. من جذر هذه الحزمة أنشئ ملف `.clasp.json` محليًا:

```json
{
  "scriptId": "NEW_BOUND_STORE_SCRIPT_ID",
  "rootDir": "src"
}
```

```sh
clasp login
clasp status
clasp push
```

استخدم `src` مع clasp أو انسخ `apps-script-ready` يدويًا؛ لا تجمع المجموعتين في المشروع نفسه. راجع `clasp status` ومعرف المشروع قبل الدفع. هذه الأوامر لا تنشئ إعدادات الدخول ولا تشغّل `setupStore()` ولا تنشر نسخة Web app تلقائيًا. انشر يدويًا من Google بعد المراجعة. لا تضع رموز OAuth أو `.clasprc.json` أو بيانات عملاء في المستودع. عند تحديث الكود أنشئ نسخة إصدار وحدّث النشرين، ثم أعد اختبار الصلاحيات والطلب.

## الإعلانات والخصوصية

تُحفظ قيم `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content` المختصرة مع الطلب. جهّز رابط الحملة إلى عنوان نشر المتجر مباشرةً، ومرر المعاملات فيه. تحتاج قراءة المعاملات داخل إطار HTML Service وتجربة الإحالات والتنقل إلى اختبار فعلي على النشر؛ لا تفترض أن معاينة المتصفح تحاكي سياق Google.

توجد نقاط أحداث `view_item` و`begin_checkout` و`order_submitted` عبر حدث المتصفح `store:analytics`. لا يحتوي الحدث بيانات الاسم أو الهاتف أو العنوان. لا يُطلق `purchase` بمجرد إرسال طلب مسبق، ولا توجد إضافة Meta Pixel أو اتصال بمنصة تتبع في هذا التسليم. عند إضافة منصة لاحقًا اختبر بيئة iframe، والكوكيز والموافقة والإحالة وإزالة التكرار فعليًا؛ لا تُرسل بيانات نموذج العميل أو ملاحظاته إلى المنصة.

اقرأ [حدود الأمان](docs/SECURITY.md) قبل فتح البيع. القرار النهائي بشأن المواعيد والأسعار والسياسات وطريقة الدفع يعود لعمر ومصطفى؛ نصوص التجربة لا تحل محل اعتمادها.
