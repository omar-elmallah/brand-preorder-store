# اختبارات Google قبل الإطلاق

الاختبارات المحلية تعمل ببدائل لخدمات Apps Script، ولا تُثبت نجاح النشر أو OAuth أو الهوية أو تزامن خدمات Google. **هذه القائمة لم تُنفّذ على حساب Google ضمن التسليم المحلي.** نفذها باستخدام بيانات وهمية واضحة؛ لا تستخدم بيانات عميل حقيقي للتجربة.

دوّن تاريخ التنفيذ، وحساب المنفذ، ومعرف إصدار النشر، والنتيجة. لا تحفظ بريد عميل أو هاتفه في تقرير عام.

| الاختبار | الإجراء | النتيجة المطلوبة |
|---|---|---|
| استقلال المشروع | أنشئ مشروعًا جديدًا وشغّل `setupStore()` مع قائمة الإدارة | شيت جديد خاص بعلامة المشروع، دون فتح مشروع آخر |
| تكرار الإعداد | أضف طلبًا تجريبيًا ثم أعد `setupStore()` مرتين | نفس الشيت والطلبات، لا صفوف ديمو مكررة ولا استبدال لإعداداتك |
| رفض شيت أجنبي | في مشروع اختبار منفصل ضع معرف شيت اختبار غير معلّم قبل الإعداد | رفض العملية دون تعديل الشيت الأجنبي؛ لا تختبر على NAGY STUDIO |
| متجر بلا حساب | افتح نشر المتجر بحساب مستقل أو نافذة خاصة وفق صلاحيات النشر | عرض المنتج وإرسال الطلب دون حساب عميل؛ لا عرض لبيانات الإدارة |
| إدارة عمر | افتح **نشر الإدارة** بخيار التنفيذ باسم المستخدم، مع `?admin=1` | حساب عمر المصرح له يقرأ الإدارة بعد موافقة OAuth اللازمة |
| إدارة مصطفى | افتح النشر نفسه بحساب مصطفى الذي يملك تحرير الشيت الجديد | دخول ناجح، مع ظهور مصطفى كمنفّذ للتعديل في التدقيق |
| هوية غير متاحة | اختبر نوع الحساب وسياسة Workspace المستخدمة فعليًا | إذا كانت الهوية فارغة أو غير مطابقة: رفض؛ لا منح صلاحية تلقائيًا |
| منع حساب ثالث | افتح الإدارة بحساب Google غير موجود في القائمة | رفض الصفحة ورفض كل RPC إداري، بما في ذلك القراءة والاستعادة والإعدادات |
| مستخدم مجهول | افتح `?admin=1` من نشر المتجر دون تسجيل دخول | لا بيانات عميل أو إحصاءات خاصة |
| RPC مباشر | من سياق HTML Service حاول استدعاء واجهات الإدارة دون صلاحية | رد رفض، حتى مع تغيير عناصر الصفحة أو إظهار أزرار مخفية |
| المسار الكامل | اختر الأسود ثم البرجندي، المقاس والكمية، والمحافظة، وأرسل طلب ديمو | الإجمالي صحيح، رقم طلب واضح، وظهور الطلب وبنوده في إدارة الديمو |
| فصل المواعيد | راجع قسم preorder وملخص الطلب لكل محافظة | موعد التجهيز للشحن منفصل بوضوح عن مدة التوصيل |
| منع بيع غير جاهز | احتفظ ببيانات تجريبية أو امسح إعدادًا لازمًا ثم جرّب `test_mode=false` | لا قبول لطلب حقيقي؛ تظهر أسباب الجاهزية دون أسرار |
| SKU مغلق | عطّل لونًا/مقاسًا، ثم جرّب طلبًا قديمًا من متصفح لم يحدث الكتالوج | يرفض الخادم SKU غير المتاح |
| سعر قديم في المتصفح | افتح النموذج ثم غيّر السعر/الشحن الخاص بالتجربة | يعتمد الخادم السعر الحالي؛ راجع تطابق الملخص ولا تعتمد واجهة قديمة |
| حقول غير صالحة | هاتف غير مصري، كمية صفر/كسر/كبيرة، نص طويل، محافظة غير موجودة | رفض واضح، دون طلب ناجح أو بيانات خطأ داخلية |
| حقن الصيغ | أدخل نص اختبار يبدأ بـ `=` أو `+` في حقل نصي يسمح به | قيمة نصية في الشيت، لا معادلة قابلة للتنفيذ |
| حقن HTML | أدخل نصًا مثل `<img src=x onerror=alert(1)>` في اسم/ملاحظة اختبار | يظهر كنص في الإدارة، دون تنفيذ HTML/JavaScript |
| تكرار الطلب | أرسل الحمولة نفسها مرتين بنفس `idempotency_key` | نفس رقم الطلب، صف طلب واحد وبنود واحدة |
| مفتاح وحمولة مختلفة | أعد نفس المفتاح مع تغيير الكمية أو العنوان | رفض التعارض؛ لا تعديل للطلب السابق |
| فقد الاستجابة | اقطع اتصال المتصفح حول الإرسال ثم أعد نفس الطلب والمفتاح | لا ازدواج في الطلبات؛ استعادة النتيجة أو طلب إعادة محاولة آمنة |
| آخر سعة | حدد سقف SKU تجريبيًا، وأرسل طلبين متزامنين يتجاوز مجموعهما السقف | لا تجاوز للسعة؛ نجاح ما تسمح به السعة فقط |
| إلغاء متكرر | ألغ طلبًا مرة ثم أعد طلب الإلغاء | إرجاع السعة مرة واحدة؛ لا مضاعفة للسعة |
| تجربة مقابل حقيقي | قارن سجلات وملخصات الديمو والحقيقي في بيئة اختبار | فصل السعة والإحصاء والتحصيل حسب الوضع |
| فشل جزئي | في نسخة اختبار فقط حقن فشل بعد صف الطلب وقبل اكتمال البنود | لا رسالة نجاح مبكرة؛ الاستعادة لا تترك طلبًا ناجحًا ناقص البنود |
| سجل دفع | سجّل تحصيلًا جزئيًا ثم تكملة ثم استردادًا مع ملاحظة | حالة الدفع والمبالغ صحيحة، وحالة الطلب مستقلة، وتدقيق إداري مقتضب |
| إعادة محاولة الدفع | أعد نفس عملية التسجيل بنفس `mutation_key` | لا احتساب للتحصيل أو الاسترداد مرتين |
| الدفع عند الاستلام | أنشئ طلبًا بإعداد COD | الحالة غير مدفوع حتى تسجيل تحصيل إداري فعلي |
| واتساب | افتح رابط تأكيد أو تحديث شحن من الإدارة | رسالة معدة للمراجعة؛ لا إرسال تلقائي |
| حماية الإساءة | جرّب honeypot وزمن أقل من المسموح وتجاوز حدود تجربة صغيرة | رفض/إبطاء مناسب دون كشف أسرار؛ توثيق أن الحماية محدودة |
| UTM | افتح رابط النشر بـ UTM واضحة وأرسل ديمو | القيم المختصرة محفوظة؛ لا بيانات عميل في URL أو أحداث القياس |
| أحداث المتصفح | راقب `store:analytics` في HTML Service على النشر الحقيقي | أحداث view_item/begin_checkout/order_submitted بلا بيانات شخصية، ولا purchase تلقائي |
| الهاتف والوصول | اختبر شاشة صغيرة، لوحة المفاتيح، الرسائل والتباين والجدول | اتجاه RTL سليم، لا تمرير أفقي معيق، ويمكن إتمام الطلب |
| تحديث النشرين | حدّث إصدار الكود في المتجر والإدارة | يعمل الإصدار المقصود في النشرين، مع إعادة اختبار السماح والرفض |
| الحصص والتعافي | راجع Executions وحجم التجربة وحدود الحساب | لا أخطاء خفية، وتوجد آلية إغلاق يدوي ومراجعة للمعلقات |

لا تختبر الفشل الجزئي أو تغيير المعرفات أو الحدود على متجر يقبل طلبات فعلية. استخدم نسخة مستقلة وشيت اختبار جديدين. لا تُعرض هذه القائمة كاختبارات ناجحة حتى تُسجل نتائجها الفعلية.
